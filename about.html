소개

왜 만들었나

시험 기간에 노트를 다섯 번 읽고 시험장에 들어갔는데, 막상 백지가 되는 경험을 한 적이 있습니다. 나중에 알고 보니 반복해서 읽는 공부는 익숙함을 만들 뿐, 기억에서 꺼내는 능력은 거의 늘려주지 못한다고 하더군요. 실제로 기억을 붙잡아 주는 건 스스로 문제를 풀어보는 인출 연습이었습니다.

문제는 그게 귀찮다는 것입니다. 문제집은 내 교수님 범위와 다르고, 직접 만들자니 노트를 처음부터 다시 읽어야 합니다. 그 귀찮음을 없애면 사람들이 더 나은 방식으로 공부할 것 같아서 만들었습니다.

어떻게 동작하나

API 키는 브라우저에 절대 내려가지 않습니다. 브라우저는 우리 서버리스 함수만 부르고, OpenAI 호출은 서버에서만 일어납니다.

브라우저 — quiz.html 에서 노트 입력 → 프론트 유효성 검사
↓ fetch('/api/quiz', { method: 'POST' })
Vercel Serverless Function — api/quiz.py (Python) · 환경 변수에서 API 키를 읽음
↓ HTTPS + Authorization 헤더
OpenAI Chat Completions API — JSON 모드로 문제 생성
↑ JSON 응답 검증 후 그대로 전달
브라우저 — 문제 카드 렌더링 (정답은 접힌 상태)

각 부분의 역할

  • HTML화면의 구조. 어떤 내용이 어떤 순서로 있는지를 정합니다. (header, form, textarea, article)
  • CSS화면의 표현. 색·간격·배치와 화면 크기별 레이아웃, 다크 모드 색상 전환을 담당합니다.
  • JavaScript화면의 동작. 입력 검증, fetch 요청, 응답을 DOM으로 그리기, 오류 안내를 담당합니다.
  • Python (api/)브라우저가 해서는 안 되는 일. API 키 보관, 외부 AI 호출, 응답 검증을 담당합니다.

기술 스택

  • 프론트엔드HTML5 / CSS3 / Vanilla JavaScript (ES6+) — 프레임워크 없음, 빌드 단계 없음
  • 백엔드Vercel Serverless Functions (Python 3.12, BaseHTTPRequestHandler)
  • AIOpenAI Chat Completions API (gpt-5-mini, JSON 응답 모드)
  • HTTPrequests — 타임아웃과 상태 코드를 명시적으로 처리
  • 배포GitHub → Vercel 자동 배포 (main 브랜치 push 시 재배포)
  • 환경 변수OPENAI_API_KEY, OPENAI_MODEL(선택) — Vercel 프로젝트 설정에만 저장

개인정보 처리

  • 입력한 노트와 생성 결과를 서버에 저장하지 않습니다. 데이터베이스가 없습니다.
  • 서버 로그에는 요청 길이와 처리 결과만 남기고, 노트 본문은 기록하지 않습니다.
  • 브라우저 localStorage에는 다크 모드 설정값만 저장합니다.
  • 문제 생성 과정에서 노트 본문이 OpenAI 서버로 전송됩니다. 기밀 자료는 넣지 마세요.
  • 로그인이 없으므로 이메일·이름 등 어떤 개인 식별 정보도 수집하지 않습니다.

한계

AI가 만든 문제는 복습 보조 도구이지 공식 기출문제가 아닙니다. 드물게 노트에 없는 내용이나 애매한 정답이 나올 수 있으니, 최종 판단은 교재와 강의자료를 기준으로 하세요. 이미지·PDF 업로드, 수식이 많은 노트, 오답노트 저장 기능은 아직 지원하지 않습니다.
