## 2. 기획 배경과 목적

### 2.1 문제 정의

시험 기간에 학생들이 실제로 하는 공부는 대부분 **"읽기"** 에 머문다.
노트를 여러 번 읽으면 내용이 익숙해지기 때문에 "안다"고 착각하지만,
막상 시험지를 받으면 설명하지 못한다. 이것을 인지심리학에서는
**유창성 착각(fluency illusion)** 이라고 부른다.

이 착각을 깨는 가장 효과적인 방법은 **인출 연습(retrieval practice)**,
즉 스스로 문제를 풀어보는 것이다. 하지만 문제는 다음과 같다.

- 시중 문제집은 **내 교수님이 강조한 범위와 다르다.**
- 스스로 문제를 만들려면 노트를 다시 정독해야 해서 **시간이 너무 오래 걸린다.**
- 기출문제는 과목에 따라 **아예 존재하지 않는 경우**가 많다.

### 2.2 목적

**"내 노트"에서 곧바로 "내 문제"를 만든다.**
학생이 이미 가지고 있는 강의노트·교재 요약·필기 텍스트를 그대로 붙여넣으면
30초 안에 문제와 해설이 나오게 해서, 인출 연습의 진입 장벽을 없애는 것이 목표다.

### 2.3 성공 기준 (측정 가능한 목표)

| 지표 | 목표 |
|---|---|
| 노트 붙여넣기 → 문제 출력까지 걸리는 시간 | 30초 이내 |
| 생성된 문제 중 노트에 근거가 있는 문제 비율 | 100% (노트 밖 지식으로 출제 금지) |
| 모바일에서 가로 스크롤 발생 | 0건 |
| 실패 시 사용자가 다음 행동을 알 수 있는 안내 문구 | 모든 실패 케이스에 제공 |

## 3. 타겟 사용자

### 3.1 주 타겟 — 시험을 2주 앞둔 대학생

- 강의자료(PPT 요약, 필기, 교재 정리)를 텍스트로 가지고 있다.
- 범위는 넓은데 어디서부터 확인해야 할지 모른다.
- 문제집을 살 예산과 시간이 없다.

### 3.2 부 타겟

- **자격증·어학 독학자** — 교재를 요약해 스스로 점검하고 싶은 사람
- **스터디 그룹 운영자** — 매주 모임 전에 퀴즈를 준비해야 하는 사람
- **조교·튜터** — 수업 후 확인 문제를 빠르게 뽑아야 하는 사람

### 3.3 사용자 시나리오

> 3학년 지수는 내일 '운영체제' 중간고사다.
> 교수님이 올린 강의노트 8장 중 3장(프로세스 스케줄링)이 불안하다.
> 퀴즈노트에 해당 부분을 붙여넣고 `난이도: 어려움`, `문제 수: 8개`로 생성한다.
> 15초 뒤 객관식 5문제 + OX 1문제 + 주관식 2문제가 나온다.
> 답을 가린 채 풀어보고, '해설 보기'를 눌러 틀린 2문제의 개념만 노트에서 다시 찾아 읽는다.

## 5. 핵심 기능

### 5.1 AI 퀴즈 생성 (필수 · 1개)

| 구분 | 내용 |
|---|---|
| 사용자 가치 | 내 노트 그대로에서 시험 문제를 얻어, 읽기 공부를 풀기 공부로 바꾼다 |
| 입력 UI | `<textarea>` (노트 본문) + 난이도 `select` + 문제 수 `select` + 유형 체크박스 |
| 호출 방식 | 프론트 `fetch('/api/quiz', { method: 'POST' })` → Vercel Python 함수 → OpenAI API |
| 출력 | 문제 카드 목록 (문항 번호 / 유형 배지 / 질문 / 보기 / 정답 / 해설 / 근거 문장) |

### 5.2 보조 기능

| 기능 | 설명 |
|---|---|
| 답 가리기 | 기본값은 정답·해설이 접힌 상태. 클릭해야 펼쳐진다 (인출 연습 강제) |
| 전체 복사 | 생성 결과를 마크다운 텍스트로 클립보드에 복사 |
| 텍스트 저장 | `.txt` 파일로 내려받기 (서버 저장 없이 브라우저에서 생성) |
| 글자 수 카운터 | 입력 길이를 실시간 표시, 상한(8,000자) 초과 시 경고색 |
| 예시 노트 넣기 | 버튼 한 번으로 샘플 노트를 채워 바로 체험 |
| 다크 모드 | 라이트/다크 토글, `localStorage`에 저장, 시스템 설정 자동 감지 |

## 6. AI 기능 상세 명세

### 6.1 입력 규격

| 필드 | 타입 | 필수 | 제약 | 기본값 |
|---|---|---|---|---|
| `notes` | string | ✅ | 30자 이상 8,000자 이하 | — |
| `difficulty` | string | ❌ | `easy` \| `normal` \| `hard` | `normal` |
| `count` | number | ❌ | 3 ~ 10 | 5 |
| `types` | string[] | ❌ | `multiple` \| `ox` \| `short` 중 1개 이상 | 전체 |

### 6.2 출력 규격 (JSON)

```json
{
  "ok": true,
  "topic": "프로세스 스케줄링",
  "quizzes": [
    {
      "no": 1,
      "type": "multiple",
      "question": "선점형 스케줄링에 해당하는 것은?",
      "choices": ["FCFS", "SJF(비선점)", "Round Robin", "우선순위(비선점)"],
      "answer": "Round Robin",
      "explanation": "Round Robin은 타임 퀀텀이 끝나면 CPU를 강제로 회수하므로 선점형이다.",
      "evidence": "노트 중 '타임 퀀텀 만료 시 문맥 교환' 부분"
    }
  ]
}
```

- `type` 이 `ox` 이면 `choices` 는 `["O", "X"]`, `short` 이면 빈 배열이다.
- `evidence` 는 **노트 안에서 근거가 된 부분**을 가리킨다. 모델이 노트 밖 지식으로 문제를 만드는 것을 억제하기 위한 장치다.

### 6.3 프롬프트 설계 원칙

1. **역할 고정** — "주어진 노트 범위 안에서만 출제하는 출제자" 로 역할을 고정한다.
2. **범위 제한** — 노트에 없는 내용은 출제하지 말고, 근거가 부족하면 문제 수를 줄이도록 지시한다.
3. **형식 강제** — `response_format: { "type": "json_object" }` 로 JSON 응답을 강제한다.
4. **언어 일치** — 노트의 언어를 따라간다(한국어 노트 → 한국어 문제).
5. **오답 품질** — 객관식 오답 보기는 "명백히 틀린 것"이 아니라 "헷갈릴 만한 것"으로 만들게 한다.

### 6.4 실패 처리 기준 (요구사항 5번 — 3종 모두 구현)

| # | 상황 | 감지 위치 | HTTP | 사용자에게 보이는 메시지 |
|---|---|---|---|---|
| 1 | 입력이 비어 있음 | 프론트(전송 전) | — | "강의노트를 먼저 붙여넣어 주세요." + 입력창 포커스 |
| 2 | 입력이 너무 짧음 (30자 미만) | 프론트 + 백엔드 | 400 | "문제를 만들기엔 내용이 너무 짧아요. 30자 이상 입력해 주세요." |
| 3 | 입력이 너무 김 (8,000자 초과) | 프론트 + 백엔드 | 413 | "노트가 너무 깁니다. 8,000자 이하로 나눠서 시도해 주세요. (현재 N자)" |
| 4 | 유형 미선택 | 프론트 | — | "문제 유형을 최소 하나 선택해 주세요." |
| 5 | 서버 키 미설정 | 백엔드 | 500 | "서버 설정에 문제가 있습니다. 잠시 후 다시 시도해 주세요." |
| 6 | OpenAI 인증 실패 (401) | 백엔드 | 502 | "AI 서비스 인증에 실패했습니다. 관리자에게 문의해 주세요." |
| 7 | 요청 한도 초과 (429) | 백엔드 | 429 | "요청이 몰리고 있어요. 30초 뒤에 다시 시도해 주세요." |
| 8 | AI 서버 오류 (5xx) | 백엔드 | 502 | "AI 서버가 응답하지 않습니다. 잠시 후 다시 시도해 주세요." |
| 9 | 응답 지연 / 타임아웃 | 백엔드 50초 + 프론트 55초 | 504 | "응답이 너무 늦어졌습니다. 노트를 조금 줄이거나 문제 수를 줄여 다시 시도해 주세요." |
| 10 | JSON 파싱 실패 | 백엔드 | 502 | "AI 응답 형식이 올바르지 않습니다. 다시 시도해 주세요." |
| 11 | 네트워크 끊김 | 프론트 | — | "인터넷 연결을 확인해 주세요." |

**공통 원칙**

- 모든 오류 메시지는 **원인 + 사용자가 할 수 있는 다음 행동**을 함께 담는다.
- 기술적 세부 정보(스택 트레이스, API 키, 내부 URL)는 화면에 절대 노출하지 않는다.
- 오류가 나도 사용자가 입력한 노트는 지우지 않는다.
- 요청 중에는 버튼을 비활성화해 중복 호출과 과금을 막는다.

## 8. 데이터 및 개인정보 처리

- 입력한 노트와 생성 결과는 **서버에 저장하지 않는다.** (DB 없음, 로그에 본문 미기록)
- 브라우저 `localStorage`에는 **다크 모드 설정값만** 저장한다.
- OpenAI API 호출 시 노트 본문이 OpenAI 서버로 전송되므로, 사용법 페이지에
  "개인정보·기밀 자료는 붙여넣지 마세요" 안내를 명시한다.
- API 키는 Vercel 환경 변수(`OPENAI_API_KEY`)로만 관리하며, 클라이언트 코드에는 어떤 형태로도 포함하지 않는다.

## 9. 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 프론트엔드 | HTML5 / CSS3 / Vanilla JS (ES6+) | 과제 제약. 빌드 도구 없이 바로 배포 가능 |
| 스타일 | CSS 변수 + Flexbox/Grid + 미디어 쿼리 | 다크 모드를 변수 교체만으로 구현 |
| 백엔드 | Vercel Serverless Functions (Python 3.12) | 서버 관리 없이 API 키를 안전하게 숨김 |
| HTTP 클라이언트 | `requests` | 타임아웃·상태 코드 처리가 명시적 |
| AI | OpenAI Chat Completions (`gpt-4o-mini`) | 저비용, JSON 모드 지원 |
| 배포 | Vercel + GitHub 연동 | push 시 자동 재배포 |
